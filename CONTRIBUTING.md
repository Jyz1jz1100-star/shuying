# Contributing

Use the [development guide](docs/development.md) for Windows setup, tests, and packaging. Run pytest, pnpm typecheck and pnpm build for code changes. For documentation-only changes, check accuracy and links. Mock model calls in ordinary tests; opt-in real-model checks must record model and hardware.

Priorities: source attribution, preservation of original/human text, checkpoint recovery and reproducible installation. A citation is a navigation aid, not a truth label.

Keep PRs focused: describe the user-visible problem, behavior change and checks run. Add regression tests for data-loss, resume or citation bugs. Reuse existing components before adding dependencies.

Never include keys, private media, personal logs, databases, models or build outputs. Use self-authored or explicitly licensed samples. The demonstration subtitle is original project material under MIT.

For security issues, avoid public credentials or sensitive reproduction data. Use GitHub private vulnerability reporting if enabled; otherwise request a private contact without disclosing sensitive details.

Keep both READMEs focused on users: explain everyday uses, download, first use, and relevant limitations in plain language. Cover courses, interviews, podcasts, recordings, and existing subtitles without restricting the audience to technical-video authors. Put source setup, test/build commands, architecture, and agent/developer instructions in their dedicated documents. Keep Chinese and English introductions aligned and describe only implemented capabilities.
