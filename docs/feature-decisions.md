# 功能取舍与迭代记录

目标：易上手、独立有用、能接着用其他工具处理。每项功能都应缩短一个真实任务的路径；没有使用就不应增加模型下载、后台处理或配置负担。

## 本轮选择

| 需求 | 必要性与取舍 | 本轮结果 |
| --- | --- | --- |
| 点句子找回原视频 | 核对观点、数字和语境的高频操作；可复用现有字幕时间 | 工作区所选字幕提供原视频时间链接，Word/Markdown 阅读稿保留时间链接。支持 YouTube/Bilibili；其他来源不伪造时间参数 |
| 思维导图 | 长文需要先看结构；图中内容还应能回到原文 | 从现有讲义生成可折叠结构导图，节点定位原文，可导出 Markdown 大纲。无需生图服务或额外模型调用 |
| 文件树、自动整理 | 材料多时找不到，比没有目录树更紧迫 | 全任务标题/文件名/作者/链接搜索，状态和来源组合筛选；按需展开更多任务。不移动用户文件 |
| 人声提取后转写 | 背景音乐可能影响识别，但处理也可能损伤语音 | 延后。先对同一批有权使用的噪声/音乐样本比较原音频与分离音频的转写，记录错误率、耗时、内存和模型体积，再决定可选后端 |
| 合集批量下载 | 经常整理系列课程时有价值，但错误输入可能导致大量下载 | 延后。复用 yt-dlp；先预览条目、勾选数量、设总时长/容量上限、去重并支持逐项取消重试，再接入现有串行队列 |

图像生成不能替代可编辑、可导航的知识结构。这版结构导图只重新展示已有讲义，不宣称生成了新的概念关系或验证了内容正确性；没有讲义时不展示空导图入口。

## 可以继续验证的轻量需求

1. **材料重命名与手动收藏**：用户材料明显增多、现有搜索无法命中时再加；先用简单元数据，不做文件搬迁。
2. **本地多文件队列**：比开放无限合集下载更可控。先展示文件数、大小、逐项状态，默认串行，不自动触发付费笔记生成。
3. **转写词汇提示**：课程人名、产品名反复识别错误时值得做；先区分 ASR 提示与现有校对术语表，不能承诺所有转写模型都支持。
4. **重点摘录**：确有反复查找同一片段的使用反馈后再做，保留时间与来源；不顺带引入复杂笔记数据库。

加入门槛：有清楚的输入和产出，默认流程不多一步，能复用现有数据，失败不影响阅读和导出。高资源功能必须可选，有取消、重试和资源上限。

## 三轮落地

- 第一轮：补齐时间导航、结构导图、任务查找，保持现有字幕和讲义处理流程。
- 第二轮：审查发现并修复 B 站分 P 丢失、Word 无效引用显示零秒、首次音频定位需等待元数据的问题；导图保留待更新和来源不确定提示。
- 第三轮：加入导出/API/旧任务可检索回归测试和前端筛选/导图目标测试，接入 Windows CI；记录发布验证，不将代码通过等同于真实音频质量改善。

## 已参考的现有方案

- [Markmap](https://github.com/markmap/markmap)：Markdown 结构可直接驱动导图，不依赖生图。当前只需要章节与段落两层导航，先用原生折叠控件和 CSS；需要缩放、拖动或更深层结构时再评估库。
- [Buzz 文件导入](https://chidiwilliams.github.io/buzz/docs/usage/file_import)：已有可选语音提取，证明场景存在；仍需对述影所用转写链路独立评估。
- [yt-dlp](https://github.com/yt-dlp/yt-dlp)：已有合集和下载归档能力，未来复用其发现/下载机制，应用负责明确范围、资源上限和队列体验。
